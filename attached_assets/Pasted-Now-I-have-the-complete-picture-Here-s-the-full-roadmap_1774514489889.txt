## Feature A — Character Movement on the Map

Your `World` component (in `chronicles-ai/client/src/world/`) renders the 3D Mission Control floor with character sprites/meshes on tiles. Right now characters are static. Here's what needs to change:

### How It Works
Each character needs a **home tile** and a set of **crisis tiles** they move to when specific events fire. Movement is triggered from `App.jsx` by passing a `characterPositions` prop to `<World />`. 

### What to Add to `App.jsx`

```js
// Default home positions per character (tile coords on the 3D grid)
const HOME_POSITIONS = {
  KRANZ:  [0, 0, 0],
  'ENG-1': [-2, 0, 1],
  'ENG-2': [-1, 0, 2],
  'ENG-3': [1, 0, 2],
  'ENG-4': [2, 0, 1],
  'ENG-5': [2, 0, -1],
}

// Crisis positions — where they physically move during specific events
const CRISIS_POSITIONS = {
  KRANZ:  [0, 0, -1],   // steps forward to the front console
  'ENG-3': [0, 0, 1],   // rushes to the center floor
  'ENG-5': [-1, 0, -1], // moves toward the comms station
}

const [charPositions, setCharPositions] = useState(HOME_POSITIONS)

// Inside handleDecision / showBroadcast, trigger movement:
const triggerMovement = (charKey, crisis = false) => {
  setCharPositions(prev => ({
    ...prev,
    [charKey]: crisis
      ? (CRISIS_POSITIONS[charKey] || HOME_POSITIONS[charKey])
      : HOME_POSITIONS[charKey]
  }))
}
```

### What to Add to `World.jsx`
Use `useSpring` from `@react-spring/three` (already likely available since you have R3F) to smoothly animate each character mesh to its new position when `charPositions[key]` changes:

```jsx
import { useSpring, animated } from '@react-spring/three'

function Character({ charKey, targetPos, isSelected, isTalking, onClick }) {
  const { position } = useSpring({
    position: targetPos,
    config: { mass: 1, tension: 120, friction: 20 } // smooth walk feel
  })
  return (
    <animated.group position={position} onClick={onClick}>
      {/* existing mesh */}
    </animated.group>
  )
}
```

Characters will physically **glide across the floor** when crisis events fire — TELMU rushing to the center floor when O₂ drops, KRANZ stepping forward when declaring emergency.

### C3 — Mission Forking (Alternate Timelines)

Every decision that passes through `/evaluate` writes to a **timeline state** on the backend. The story branches into one of several tracked outcomes: 

| Your Decision | Physics Check | Outcome Branch |
|--------------|--------------|----------------|
| PC+2 burn correct (30.7 m/s) | ✅ Reentry 6.49° | **NOMINAL — Pacific splashdown** |
| Burn too early | ❌ Wrong trajectory | **TIMELINE B — skips atmosphere, lost** |
| Ignore CO2 warning | ❌ >15 mmHg CO2 | **TIMELINE C — crew incapacitation at T+80h** |
| Wrong power shedding | ❌ Battery depletes | **TIMELINE D — guidance failure, no reentry** |
| All correct | ✅✅✅ | **REAL HISTORY — April 17 splashdown** |

The LLM characters **know which timeline they're in**. RETRO in Timeline B doesn't pretend the crew will make it — he gives you the honest physics of what went wrong.
